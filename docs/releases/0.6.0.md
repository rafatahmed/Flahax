# FlahaX 0.6.0: detailed notes

The full text of every change in 0.6.0, as recorded when each was merged, newest first. The [changelog](../../CHANGELOG.md) groups them into a short summary.

- Release hardening from the pre-release audit (#149-#151). A damaged or hand-edited `flahax mix` session file now gives one plain error naming the file and the field (`invalid_session`, in the user guide) instead of a traceback; a malformed-input sweep of every entry point gives no traceback. CI runs the unit tests and the package check on Windows and macOS as well as Linux. The sdist includes `SECURITY.md` and `CODE_OF_CONDUCT.md`. The README explains reinstalling from GitHub between releases (#134).
- Alpha TUI trial fixes (owner trial and screen-by-screen audit, 2026-10-23). Arrow keys work in Windows Terminal (#135; #127, typing "à", stays open). Key help, inactive tabs and labels use the normal text colour instead of faint text that vanished on some themes (#137). Q or Esc on the results asks before leaving (#138). In the fertilizer filter Space types and Tab ticks, so a two-word name no longer ticks the wrong product (#139). Rounding noise prints as 0 and table columns keep apart (#140). Card headings and the footer wrap (#141). Grower words instead of internal codes in prompts and notes, on the screen, the sheet and the terminal (#142). The acid list says what was added (#143); lab values typed so far are shown (#144); the Tanks answer fits "Your batch" (#145); "more below" when a view is taller than the window (#146). The recipe stays in the terminal after the screen closes (#147). Earlier review findings #125-#132 were fixed with #124.
- Every public class, method and function has a docstring (hardening 4, #122), checked by ruff (D101-D103) and `tests/test_public_docstrings.py`.
- Lines are at most 99 characters and CI enforces it (hardening 3b, #121); text FlahaX writes out unchanged keeps its long lines with one marker.
- `flahax mix` opens full screen in a terminal (owner design 2026-10-23), with Python's standard library only: arrow keys and Enter choose, typing filters long lists, Space ticks the fertilizers available, Esc asks before quitting. The five steps go forward only; at 100 columns or more the answers so far stay in a left pane. The result opens on Tanks (tank A, tank B, the acid container), with Nutrients and Notes on Tab; a blocked batch opens on Notes. Every value comes from the same summary and rounding as the batch sheet, and the sheets are written exactly as before. The line-by-line questions stay for `flahax mix --plain`, scripts, pipes and editor panels, with byte-identical output (`tests/fixtures/mix/owner-session-plain.txt`). New modules: `flahax.terminal` (Windows `msvcrt`/`ctypes`, POSIX `termios`/`tty`/`select`; the console is always restored), `flahax.mix_tui` and `flahax.mix_results`.
- Security policy (`SECURITY.md`): supported versions, private reporting through GitHub or info@flaha.org, and what counts as a security problem. Coverage: the Python 3.13 CI job runs the tests under `coverage` (a CI tool only, pinned 7.17.0) and uploads the report to Codecov with the pinned `codecov/codecov-action` v7.1.1; `codecov.yml` makes the Codecov checks informational. The README gains Tests, Documentation (Read the Docs) and Codecov badges.
- Code of conduct: the Contributor Covenant 2.1, unchanged apart from the reporting contact (Flaha Agri Tech, info@flaha.org), linked from CONTRIBUTING.
- PEP 8 style and file headers (hardening 3a/4; owner decisions 2026-10-23: line length 99, header template). All Python code is formatted with `ruff format` (PEP 8, 99 columns; quote style kept), which leaves the code's meaning unchanged; one statement per line, PEP 8 spacing and blank lines throughout. Every Python file (161) starts with the header in PEP 8 order: a shebang only on runnable tools and examples, the SPDX copyright and license lines and the disclaimer, then the module docstring (36 test files gained one). `flahax/__init__.py` now lists `__all__` (135 names, unchanged) and `__version__` before its imports, instead of 13 `__all__ +=` lines between them. Unused imports and variables are removed (including an unused H3PO4 term in the phosphate loop; H3PO4 is still in the mass balance), two lambdas assigned to names became functions, and the ambiguous name `l` became `line`. Style settings live in `pyproject.toml` (ruff is a development tool, not a runtime dependency); a new CI `style` job runs `ruff check` and `ruff format --check`, and `tests/test_file_headers.py` checks the header order. Line length is enforced after the remaining long strings and comments are rewrapped (3b). CONTRIBUTING.md documents the conventions.
- Every error code is explained (hardening 2/4). The shipped user guide gains an error code reference: all 91 `DeliveryError` codes, grouped by what you were doing (input values and files, water analysis, products and materials, recipe and pH, chemistry model, stocks and injection, delivery plans and EC), each with its meaning and what to do; 68 were undocumented. `tests/test_error_catalogue.py` fails if a raised code is missing from the guide. A material whose formula cannot be used now says why: it cannot be read (check the brackets and the element symbols), has fractional atoms, does not split into the fertilizer ions FlahaX knows, or splits in more than one way; it said 'give its formula' even when one was given. The exception audit found no other user-facing exception outside `InputError` and `DeliveryError`: the remaining `TypeError`s are argument-type checks, the `AssertionError`s belong to the reference-fixture comparison helper, and the internal `ValueError`s are caught and re-raised.
- Entry points refuse bad input with a plain message instead of a traceback (#117, from the entry-point audit). `flahax batch --ratio 0` crashed with a ZeroDivisionError; every number option is now checked at the command line with its range (`--ratio`, `--volume` and `--max-reagent-litres` above 0, `--ph` 0-14, `--water-share` above 0 up to 100). Every JSON file (water, targets, products, rules, saved items and sessions) and JSON on stdin is read by one reader that names the file and the line and column (`missing_file`, `invalid_json`); a water value that is not a number, or a non-numeric `--acid` assay or density, is named in the message. The `flahax batch` terminal shows the acid with the same 0.1 mL rounding as the sheet and report.
- Package identity and attribution (owner decisions 2026-10-23). Metadata: author Rafat A. Al Khashan with public contact email, maintainers Rafat A. Al Khashan and Flaha Agri Tech (affiliation), a description that names the grower command and the A/B stock planning, fuller keywords, Development Status 4 - Beta, Console and end-user audiences, Python 3.14 (now also in CI), and Changelog, Citation and Growers-guide links. NOTICE now credits every data source the package ships (USGS PHREEQC 3.8.6 minteq.v4.dat and pitzer.dat, the FlahaX chelate and phase extensions, McCleskey et al. 2012, Pethybridge et al. 2006, the CRC Handbook, Yara, the U.S. Coast Guard CHRIS database, Haifa, Sigma-Aldrich, ChemicalBook, SQM and the crop-formula authors) and reproduces the USGS User Rights Notice, which applies to PHREEQC data: it requires modified data to say what changed, by whom and when, so chemistry_25c.json and NOTICE now carry that statement (the sylvite constant, from pitzer.dat, was not credited before). CITATION.cff gains a current abstract, release date, affiliation, contact and a references list checked against Crossref. The README gains an Author and credits section; `tests/test_attribution.py` fails if a shipped data source is not credited. Zenodo archiving is documented as an owner step in the publishing procedure.
- Fix what the pre-release sweep of `flahax mix` found (19 farmer sessions, each checked across terminal, sheet at every depth and report): an unknown acid formula ('1') was accepted and the acid then silently ignored, so the plan said none was offered (#112); `flahax mix` now asks again and `flahax batch --acid` stops with the list of acids FlahaX plans with (HNO3, H3PO4, H2SO4, C6H8O7; any case). A blocked pH plan repeated its review notes (#113): a chemistry review row or advisory is listed only when not already said. A changed or new formula was titled with its file name (#114): the name typed is kept in the session and used as the title.
- Every output of one batch now agrees (#107-#110), found by generating the owner's session at all three depths. The agronomist sheet's pH path and the report's 'go from pH' used the first recipe's pH (6.71) while the report's chemistry used the weighed recipe (7.93), whose nitrate salts are reduced by the acid's nitrate: all now show the weighed recipe mixed without its reagent (`summary['ph']['mixed_ph']`), and the report also names the first recipe's pH. Weights and acid volumes use one format on the terminal, sheet and report (no more '0' weights or 86 vs 85.7 mL); each warning appears once (the pH stage no longer repeats the review rows and the iron(II) advisory); the report shows '1:100' and the status in words. A new test (`tests/test_output_consistency.py`) runs the owner's session once and checks every shared number across terminal, sheet at each depth, report and summary. Recipes and chemistry are unchanged.
- `flahax mix` finds a saved session by the name you typed (spaces, capitals, with or without `sessions/`), `flahax mix sessions` lists them, and a miss lists them too; small weights show 2-3 decimals and never read '0 g'; in fill mode the outputs say which container sets the batch ('your 10 L acid container sets the batch') (#105).
- Plain `flahax` at a terminal shows where to start (`flahax mix` for growers) instead of waiting silently for JSON; `flahax --version` works; the usage line says `flahax`, not the path to python.exe; Ctrl+C prints 'Stopped.' without a traceback (#102). Piped JSON requests work as before.
- A water report without chloride is no longer blocked (#100, owner decision 2026-10-23). Every lab report is slightly out of charge balance; FlahaX closes the gap at the measured pH on chloride, and now, when chloride is not measured, zero or below detection, on the alkalinity (the carbonate the measured pH depends on) instead (`reconciliation='closed_on_alkalinity'`). This is noted in the full report only and does not put the plan in review. The entry note and 'ask your lab' messages from #101 are replaced; RO water is unaffected. The growers page and the report explain why a lab report is balanced and why FlahaX calculates pH.
- Field test of `flahax mix` (2026-10-23): fix what a first session ran into. The formula step listed nothing and Enter looped on 'This one is needed.' (#98): Enter now lists every formula (and every chemical in step 4) to choose by number, a miss says how to see the list, and the step says the fertilizers come in step 4. A blocked plan said 'do not mix' while showing unrelated notes, because the ph_adjustment and formulation blocks carried no message: they now say why ("the feed mixes at pH 6.90 and needs an acid to reach pH 5.80; none was offered: add an acid", each candidate's reason, a declared maximum broken, or the targets missed by more than 1 %), and that reason comes first. The terminal no longer points to a report.html it did not write; small batches show their volume (0.01 L, not 0 L); a water analysis that fails the 5 % screen can be corrected one value at a time instead of retyped; the engine says 'None of the available products supplies B' instead of 'No salt in this library'. `main` now carries 0.6.0.dev0 (#99), so installing from GitHub with `--upgrade` replaces an installed 0.5.0; the publishing procedure opens the next development version after each release, and CITATION.cff keeps the released version.
- Package sourced stock solubility for 20 products (owner approval 2026-10-23), so `flahax mix` and `flahax batch` check that each concentrate dissolves at the entered temperature. Values are the CRC Handbook aqueous solubility table (18 products, 0-40 °C), Yara's CALCINIT sheet for calcium nitrate (ag grade; its 20 °C value is a floor from 20 to 40 °C, not checked below 20 °C) and the U.S. Coast Guard CHRIS compilation for urea, converted to grams of product as sold per litre at a density of 1 g/cm3: a lower bound, so a stock that would not dissolve is never passed. The six chelates, CH - micro and potassium citrate have no sourced data and stay `not_checked`. Checks remain single-salt in pure water, with no safety margin.
- Accept correctly printed supplier labels (#93, owner decision 2026-10-23). A label's charge balance against its chemical may now differ by up to 1 % (was 0.1 %): printed values are rounded and commercial grades are not the pure salt, so Yara's YaraLiva Calcinit label (N-NO3 14.4 %, N-NH4 1.1 %, CaO 26.3 %; -0.56 %) was refused. A one-point typing error (Ca 19.8 % for 18.8 %) moves the balance by about 2 % and is still refused. One limit now serves supplier grades and materials defined by formula or ions. An old magnesium nitrate analysis (N 11.0 %, Mg 9.65 %; 0.55 %) is no longer flagged.
- Open FlahaX to growers and agronomists with `flahax mix`, an interactive five-step entry (specification, water analysis, crop formula, fertilizers available, pH requirement) that saves waters, formulas, product stores, acids and sessions under `$FLAHAX_HOME` (default `~/.flahax`) in the formats `flahax batch` reads, and writes a batch sheet at the chosen depth: grower (tank A and tank B cards with prepared litres and grams, the acid container, checks after mixing), agronomist (adds the nutrient table: target, from water, required, achieved, final, difference; limits; pH path) or developer and manager (adds the full report). Lab reports are typed in their own units (mg/L, meq/L, mmol/L, alkalinity as CaCO3, micronutrients in mg/L or µmol/L); Enter is not measured, 0 a measured zero, `<DL` below detection; missing alkalinity is flagged at entry. Stock volumes follow the fill mode: fill the tanks full (the smallest container sets the irrigation volume) or make one irrigation (`stock_volumes.prepare_stocks`, `tank_too_small`). Two concentrate tanks (owner decision 2026-10-22): magnesium sulfate shares tank B with the phosphates, a waiver of Yara p. 65 listed on the report; a compound containing phosphate goes to tank B; more than two tanks is refused (`too_many_tanks`). Supplier label grades enter the chemistry and pH stages (graded id `<catalogue id>+<grade_id>`; an inconsistent label is `identity_inconsistent`), and compounds are declared from their data sheet (`declared_ions`: nitrogen forms, oxides, micronutrients, chelating agent, optional Na and Cl; checked by implied protons per phosphate between HPO4 2- and H2PO4-; one flag per unstated ion; their chelate sodium counted in the Na row); a product that cannot be modelled is formulated but gets no pH plan (`ph_not_planned_for_product`). Stock solubility is checked per product at the entered temperature from sourced data (`stock_solubility.check_stock_solubility`); no data is packaged yet, so every product shows not checked until the owner approves the sourced table. The review reasons on every output now quote the recipe that is weighed (#91).
- A material is defined by what it puts in the water, not by its catalogue name (owner decision 2026-10-22). `material_chemistry(record)` resolves a compound from its stated `ions` (with `chelating_agent` for chelates) or its `formula` (fertilizer ion table plus hydrate water), and a blend from its analysis by nutrient form (declared-ions grade); a record with only a name stops with `material_undefined` and says what to give. The 32 catalogue products are pre-filled materials whose ions are their identities' `ion_forms`; counterions and ligands follow the ions, so the name-based special cases (potassium carbonate and bicarbonate, macro-salt formula counterions) are gone. `chemistry_for_product`, `PRODUCT_CHEMISTRY` and `convert_catalogue_product_dose` remain as views. Every catalogue product converts bit for bit as before at five doses, and the 26 packaged formulas in RO water give identical recipes, pH and reagent decisions; a material list that shares no names with the catalogue gives the same recipe, pH and acid dose as the catalogue. Urea's component list was a string (a missing tuple comma) and is now a tuple.
- Assess untargeted nutrients once, and name where each comes from (#92). `recommend` keeps its 10 % ammonium allowance (`ammoniumLimit`), but the workflow re-assessed the first fit against the caller's limits only, so ammonium within the allowance read 'no declared maximum' and made the formulation `requires_review` while the coupled pH refit rated it `within_limit`. The workflow now assesses against the caller's limits plus the allowance `recommend` applied (a declared N_NH4 maximum still wins; an explicit N_NH4 target is fitted as given), so first fit, refit and every later stage agree. Every incidental row carries `source`, the dosed products (or water) that supply it, e.g. N_NH4 from Calcium Nitrate (ag grade), and the summary's formulation rows for untargeted nutrients carry it too. Recipes are unchanged: the 26 packaged formulas in RO water give identical salts, first fit and refit.
- Draft the physical validation protocol (#41): what will be measured (acid dose to target pH, pH after the planned dose, stock-tank stability with a precipitating positive control, nutrient concentrations; unadjusted pH and EC reported only), a 2-water by 3-formula matrix with three independent preparations, predictions made from measured inputs and frozen by commit hash before any solution is prepared, proposed acceptance criteria, fixed exclusions, and the separation of implementation agreement, input uncertainty and measured agreement. No measurement has been made; reviewer, laboratory and budget are the owner's decisions.
- Benchmark the authors' Irriblend-DSW optimiser in the competitor comparison (#40). Its authors added the MIT licence on 2026-10-20 (commit a046d5c), so the formulation track now imports their unmodified `irriblend_dsw_funs.py` (SHA-256 checked) and calls `ferti_eco_min`; through the same calls it reproduces all 97 water blends of their two published case-study outputs exactly. The independent LP after their method stays beside it, and every engine is also scored on macronutrients only, because Irriblend-DSW models no micronutrients. New snapshot 2026-10-22-competitors-1ade5b6: on the benchmark's fixed inputs (equal prices, non-binding EC cap) the optimiser returns 30 of 52 recipes, meets N, P, K and S in every one, and overshoots Mg or Ca as its lower-bound constraints allow; the comparison page explains each result. All other accuracy figures are unchanged from the previous snapshot.
- Rewrite the growers page as a task path (#80): enter the water analysis (with unit conversions, measured zeros and detection limits), choose the formula, run `flahax batch`, read the batch sheet; then a worked tomato example on the station 104 well blended with RO water (8% passes the 3 mmol/L Na and Cl limits, 9% is blocked), what to measure after mixing and when to call an agronomist. A test reruns the example and checks the page's numbers. `flahax batch --water-share PERCENT` blends the analysed water with ion-free water: nutrients and limits scale the laboratory values and the chemistry dilutes the measured-pH record (#84). Formulation and pH stages that need review now say why (incidental nutrients without a declared maximum; the chosen reagent's review findings and missed targets) instead of an empty reason.
- Fix `recommend()` raising 'NNLS did not reach optimality' when the source water alone exceeds one declared maximum while another is binding (#86), for example 9% of the station 104 well with Na and Cl maxima of 3 mmol/L. A ceiling the water already reaches cannot be met, so its Lagrange search grew the shift without bound (#68) until NNLS failed. Products carrying that ion are now left out of the fit directly, the infinite-multiplier limit the search was approaching, and the excess is reported in `limitViolations` as before. Over 312 formula, water-share and ceiling cases the recipes are identical wherever the old search succeeded, and the failing cases now equal the fit without chloride products.
- Concentration limits and nutrient targets now always use the laboratory water analysis; the charge-balanced water is used for chemistry only (#84). `balance_water_analysis` closes an analysis' charge on chloride or sodium, a modelling step, but its totals were passed on as the water: the nitric delivery stage rebuilt its nutrient rows and limits from them, `flahax batch` (#79) formulated on them, and the tomato example chose its blend on them. On Shomar et al. (2024) station 104 the model has 1158.5 mg/L chloride against 1280.4 measured, so the example reported 9% well water as within the 3 mmol/L chloride limit; on the laboratory value 9% is 115.2 mg/L and fails, and 8% (102.4 mg/L) is the largest passing share (boundary about 8.3%). Balancing on sodium raises sodium from 680 to 759 mg/L, so the error could also reject a passing water. Now `BalancedWaterAnalysis` keeps `analytical_totals` (the analysis as entered, defensively copied) beside the model, with its provenance, and `diluted(fraction)` blends it with ion-free water, scaling both and recomputing the blend's chemistry. The workflow accepts such a record as `equilibrium['water_balance']`, rejects contradictory water inputs, passes `analytical_water_totals` to `plan_equilibrium_delivery` (rows and limits on the analysis, dose on the chemistry), and reports laboratory and modelled water in `water_basis`. When the balancing alone would change a limit decision the plan is `requires_review` with the reason; a laboratory-basis exceedance always blocks, and a review never downgrades a block. The coupled pH planner's no-reagent-needed candidate now gets the same limit and saturation checks as dosed candidates (it skipped both), and the workflow rechecks the selected plan's limits. Balancing itself is now explicit: an analysis that already closes at its measured pH (within 0.0001% of its total charge) is used unchanged and needs no balance ion, so chloride-free waters no longer fail on the default chloride; `CO3-2` = 0 marks measured carbon-free water (omitted carbon is still `missing_carbon`); measured zeros and `below_detection` components are held fixed; the closure is `reconciled` only within a stated `balance_ion_uncertainty_percent` (else `reconciliation_out_of_bounds`), and without one it is `assumed` and the chemistry, and every plan built on it, asks for review. No other ion is tried automatically (`fixed_balance_ion`). `flahax batch` takes nutrients straight from the analysis file, accepts measured zeros, detection limits, a balance ion and its uncertainty, and gains `--limit SYMBOL=MG_PER_L`; undeclared limits are never assumed. The report shows laboratory, modelled and adjusted water, each limit with its decision basis, and the batch sheet the limits on the laboratory basis. The tomato example now blends 8% well water and every dependent number is recomputed; the publication example keeps its 1:3 blend, and only its printed blend chloride changes (290 -> 320 mg/L, the laboratory value). The grower-outputs page now gives the 5% imbalance screen (it said 10%).
- Ship the grower outputs in the package (#79). They were example code only (#73), so an installed FlahaX gave growers JSON. New `flahax batch` command: one formula (packaged, or your targets) and one water (`ro` or a measured analysis, closed at its pH) to `report.html`, `batch-sheet.html` and `summary.json`, with the coupled pH plan (your acids from certificate values, plus the packaged bases). In Python, `summarize_batch`, `render_report` and `render_batch_sheet` do the same from any `plan_fertilizer_workflow` result; when a reagent is selected the sheet weighs the refitted recipe that counts its nutrients. `group_tanks` is the sourced default concentrate grouping: the Yara page 65 compatibility table (read with page 63) as three composition rules (calcium with phosphate, calcium with sulfate, magnesium with phosphate), which reproduce its twelve incompatible pairs exactly; micronutrients and chelates go to tank A with calcium and stay out of phosphate concentrates, and tank A is never acidified (owner rule). - Positive saturation indices of phases that do not form at feed conditions no longer reject pH and delivery plans (#78). FlahaX and live PHREEQC 3.8.6 agree on every sign at the coupled target states, so the indices are right; the question was which phases form. Hydroxylapatite (precursor pathway, magnesium-inhibited), goethite (forms slowly from ferrihydrite), anhydrous MnHPO4 (unmeasured constant, log K -25.4 from 1976 program data; not reported to form at 25 C or in dilute feeds) and vivianite (Fe(II) phosphate of reducing environments; the model holds Fe(II) fixed) now make a plan `requires_review`, each with its reason and sources; feeds containing iron(II) carry an advisory that the iron oxidizes and precipitates as Fe(III) phosphate. Brushite, monetite, gypsum, struvite, calcite, ferrihydrite and every other phase, and any allocated solid, still reject. One policy (`saturation_policy.py`) now serves the coupled pH plan, acid selection, equilibrium delivery and plan validation. In the 26-formula RO-water audit at pH 5.8, 21 formulas now get a usable pH plan (12 also meet every target), against none before; the 5 still rejected have monetite or brushite supersaturated. Owner decision and cited research summary on #78.
- Plan the recipe and its pH reagent together (#74, #76, #77) and add pH-up reagents (#75). The grower-path audit found that none of the 26 shipped formulas in RO water got a usable pH plan: the recipe met N and P exactly and the acid then broke those targets (#74); a feed below the target pH had no correction at all (#75); phosphoric acid chosen as a P source drove five formulas to pH 3.0-3.4 (#76); and a 1% target miss blocked acid planning (#77). The new `ph_adjustment` workflow stage (`plan_coupled_ph`) fits the recipe without acids as nutrient salts, solves the acid or base dose to the target pH on the same equilibrium model, counts the reagent's nutrients as supply and refits until recipe and dose agree (bracketed, so recipes that switch products between nearby doses still settle). `reagent_dose` is the shared acid/base solve; `plan_acid_options` now uses it with bit-identical results. In the same audit every applicable candidate (62) now gets a computed dose at exactly the target pH (re-adding it and recalculating from scratch reproduces pH 5.8), and the five pH-3 feeds now mix at 4.5-4.9 and receive a base. All 62 are still rejected by the unchanged precipitation gate (hydroxylapatite and MnHPO4 supersaturated in every case), which #78 addresses next; each rejection names the phases and keeps the dose. The catalogue gains Potassium Hydroxide (45% solution) and Potassium Bicarbonate, and Potassium Carbonate is linked to its sourced theoretical analysis (K 56.581 -> 56.580316 %, owner-approved), all three `role: ph_reagent` and never selected as nutrient salts; sources are Sigma-Aldrich 417661, 237205 and 209619 (#75). `catalogue_ph_reagents()` returns ready reagent records for them. The catalogue now has 32 products; the mixed_target_ph_nitric PHREEQC fixture was recaptured with the pinned PHREEQC 3.8.6 because it contains potassium carbonate (nitric dose -7.8e-6 relative).
- Record the 0.5.0 publication. The published 0.5.0 manual and changelog still carry the release-candidate wording ('not yet published', 'Unreleased'); they are corrected here, and the publishing procedure now has an explicit finalize step before tagging (#71).
